Loop design

How this should trigger

The loop is useful only when a popup meaning can be automatically checked and then reviewed in a bounded owner preview.

1. TriggerNew missing high-priority terms, repaired quarantine rows, route mismatch, or visible weak popup watch.
2. CollectPull registry, route truth, backlog row packet, broad watch, full-page and bottom screenshots.
3. CouncilRun model seats for meaning, source match, learner UI, route risk, cost, and design evidence.
4. GateRequire zero unsafe shown, zero missing high-priority, no route mismatch, and visible browser proof.
5. DecideOwner marks Keep, Wait, or No. Only Keep plus a production task can graduate out of preview.

Boundaries

Use this preview when the loop conditions are true

Single prompts are still better for one-off copy edits. This loop is for repeated, source-checkable popup quality work.

Use when

Repeated popup backlog or route-risk work appears, automated registry/watch tests can fail bad output, and the owner needs a visual decision before product placement.

Do not use when

The task is one term, no source sentence exists, no automated watch can run, or the answer requires a direct human lesson-design decision.

Next redesign candidate

Add an owner-only popup proof drawer to the control room or school dashboard, then promote only after one teacher-reviewed pass.

Preview recommendation

Keep the evidence loop. Wait on production UI until the route-family difference is resolved: exact popup support exists for newer authored vocabulary rows, while some repaired terms are currently source-context only.
